# Compact research harness

Use the existing project Python runtime from the repository root:

```powershell
$researchPython = 'outputs/research_workflow/.venv/Scripts/python.exe'
& $researchPython outputs/t1_iterations/research_playbook.py
& $researchPython outputs/t1_iterations/research_harness.py status
& $researchPython outputs/t1_iterations/research_harness.py run --experiment NAME
& $researchPython outputs/t1_iterations/research_harness.py collect --experiment NAME
```

Register each predeclared experiment in RESEARCH_HARNESS_MANIFEST.json with its script, unique run directory and final report. Existing experiments are registered for collection, not rerunning. Launch refuses existing evidence, another detected project Python worker, paths outside the evidence root or a non-D: location. An exclusive lock serializes harness launches. Windows workers run hidden with two BLAS threads; full logs and receipts stay on D: in private/harness_runs. This does not impose a hard RAM limit: each scientific script must remain compatible with 16 GB RAM.

Status checks Windows process command lines and reports. It is a snapshot, not a training success certificate. An absent process without a final report is reported as interrupted_or_failed; diagnose saved stderr/events before recovery. Scripts launched through unrelated wrappers without an identifiable project path require a separate live-process check. Do not bypass the launch lock or delete evidence to restart.

Collect caches by report hash, extracts compact headlines and creates four per-metric packets. The coordinator runs four critique agents once per new completed or failed scientific batch, writes their Markdown reviews and updates state. Missing metrics stay unavailable. Collection itself does not run agents, call Jev, score predictions, certify promotion, update the ledger or change rewards. Refresh the ledger after full-panel batches. Jev receives only a cached summary of at most 3000 bytes per distinct consequential decision, never source files or datasets.

Python computation does not itself use model tokens. This harness reduces the logs and repeated orchestration material sent into model context; no measured credit saving is claimed. Use compact status/receipts for routine checks and load detailed evidence only to diagnose a meaningful change.

Fixtures and original failed test receipts remain private; no biological scores or rewards were generated by these tests.
